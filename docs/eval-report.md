# Retrieval Evaluation Report

Generated by `make eval` (`eval/run_eval.py`) against the ingested knowledge base
(74 chunks from 11 documents across tax / visa / ward_office).

## Method

For each question in `eval/datasets/*.jsonl` we record the set of relevant **documents**
(`doc_id = domain/filename`) and measure, at the document level:

- **Recall@5** — is a relevant document among the top 5 retrieved?
- **MRR** — mean reciprocal rank of the first relevant document.

Three retrieval strategies are compared on the same 7 questions (mix of English and Japanese):

- **es_only** — ElasticSearch BM25 (with the `kuromoji` Japanese analyzer).
- **qdrant_only** — dense vectors (BGE-m3) in Qdrant.
- **hybrid** — both, fused with Reciprocal Rank Fusion (k=60) and re-ranked with a
  `bge-reranker-v2-m3` cross-encoder.

## Results

| Method | Recall@5 | MRR |
|---|---|---|
| es_only (BM25 + kuromoji) | 1.000 | 0.833 |
| qdrant_only (BGE-m3 dense) | 1.000 | 1.000 |
| **hybrid (RRF + rerank)** | **1.000** | **0.929** |

## Interpretation (honest)

On this small, semantically straightforward corpus (11 documents) every method already
retrieves the relevant document within the top 5 (Recall@5 = 1.0), and dense retrieval
alone saturates rank-1 (MRR = 1.0). **Hybrid does not beat strong dense retrieval here** —
its MRR (0.929) sits between BM25 (0.833) and dense (1.000).

This is expected and is reported as-is rather than tuned to win. The value of hybrid
search shows up at scale and on queries where dense embeddings struggle but exact lexical
match helps — proper nouns, numbers, and specific Japanese terms (e.g. 確定申告, マイナンバー).
BM25 + kuromoji complements dense recall in exactly those cases; the architecture is built
so that benefit grows as the corpus and query diversity grow.

## Reproduce

```bash
make up && make ingest   # start ES + Qdrant and index knowledge/
make eval                # prints the table above
```
